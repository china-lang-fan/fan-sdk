# fan-sdk

凡语言的标准库，用凡语言自身写成。当前由 Rust 实现
[`china-lang-fan/fan-rust`](https://github.com/china-lang-fan/fan-rust) 使用。

## 用法

模块按名字导入，`作为` 后的名字由调用方自取：

```
导入 "数学" 作为 数学模块
导入 "测试" 作为 测试模块

打印行(数学模块.总和([1, 2, 3]))      // 6
```

模块查找顺序：脚本所在目录 → 环境变量 `FAN_SDK` → 可执行文件旁 →
系统安装位置。

## 原生能力的接入

标准库里凡语言写不了的部分（如 JSON 解析、正则引擎、HTTP 请求）由解释器
用原生代码实现，通过 `@内建` 标签绑定到一个凡函数：

```
@内建("json.jsonEncode")
函数 JSON编码原语(值)
    返回 空
结束
```

绑定后调用该函数即转调原生实现，函数体不再执行。名字统一用英文，可写成
`模块名.函数名`：

| 写法 | 含义 |
| --- | --- |
| `@内建("print")` | 取系统已注册的（`core` 组）内建 |
| `@内建("json.jsonEncode")` | 按模块名加载扩展库，再取其中的函数 |

模块名即动态库名（`json` → `libfan_ext_json`），找不到库时自动回落到
解释器内置的纯标准库实现。模块归属由标准库显式声明，解释器不维护
「函数名 → 模块名」的反查表。

## 测试

每个模块旁有同名的 `*_测试.凡`，其中 `函数 测试Xxx()` 即一个测试项：

```bash
fan-cli 测试 ./fan-sdk
```

当前 27 个测试文件、145 项。

新增能力时请同时补测试——这既是验收，也是两版实现行为的对齐基准。
