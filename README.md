# fan-sdk

凡语言的标准库，用凡语言自身写成。当前由 Rust 实现
[`china-lang-fan/fan-rust`](https://github.com/china-lang-fan/fan-rust) 使用。

## 目录结构

标准库按用途分目录组织，不再平铺在根目录：

```
fan-sdk/
├─ 库/      16 个库模块（含测试框架 测试.凡 与示例 模块工具.凡）
└─ 测试/    27 个 *_测试.凡，与库模块同名对应
```

## 用法

模块按根相对路径导入（统一以 `库/` 前缀），`作为` 后的名字由调用方自取：

```
导入 "库/数学" 作为 数学模块
导入 "库/测试" 作为 测试模块

数学模块.总和([1, 2, 3])      // 6
```

模块查找顺序：脚本所在目录 → 环境变量 `FAN_SDK` → 可执行文件旁 →
系统安装位置。库模块之间也用根相对路径互导（如 `导入 "库/系统"`），
不依赖导入方所在的子目录。

## 原生能力的接入

标准库里凡语言写不了的部分（如 JSON 解析、正则引擎、HTTP 请求）由解释器
用原生代码实现，通过 `本地` 绑定到一个凡函数：

```
定义 本地("json.jsonEncode") 函数 JSON编码原语(任意 值)
    返回 "", 空
结束
```

调用时**优先转调原生实现**；若找不到原生实现，则**静默回退执行函数体**，
不产生运行时错误。名字统一用英文，可写成 `模块名.函数名`：

| 写法 | 含义 |
| --- | --- |
| `定义 本地("print") 函数 ...` | 取系统已注册的（`core` 组）内建 |
| `定义 本地("json.jsonEncode") 函数 ...` | 按模块名加载扩展库，再取其中的函数 |

模块名即动态库名（`json` → `libfan_ext_json`），找不到库时自动回落到
解释器内置的纯标准库实现。模块归属由标准库显式声明，解释器不维护
「函数名 → 模块名」的反查表。

命名契约（两组，不要混用）：

- **core 组**（解释器内置、零第三方依赖）用**裸名**：`本地("print")`、
  `本地("sqrt")`、`本地("base64Encode")`。
- **ext 组**（按需加载的动态库）用 `模块.函数`：`本地("json.jsonEncode")`、
  `本地("regex.regexMatch")`、`本地("http.httpRequest")`、
  `本地("tag.tagRegisterHandler")`。

同一库模块内可能同时出现两组（如 `编码.凡` 的 JSON 走 ext、Base64/URL/Hex 走
core），这是按能力是否需要第三方依赖划分，属预期。Rust 侧模块段到动态库的
映射在 `lib_name` 显式登记，并为每个 ext 模块提供内置默认回落。

硬规则：`本地` 后必须紧跟括号且只能是单个字符串字面量；只能用于顶层函数，
不能用于类型方法；函数体必需（作为回退兜底）。当前共 71 个本地绑定，其中
仅 9 个因跨模块调用而声明为 `公开`，其余均为文件级私有。

## 测试

每个库模块在 `测试/` 下有同名的 `*_测试.凡`，其中 `函数 测试Xxx()` 即一个
测试项：

```bash
fan 测试 ./fan-sdk
```

测试发现器递归遍历子目录，当前 28 个测试文件、149 项全部通过。

新增能力时请同时补测试——这既是验收，也是两版实现行为的对齐基准。
